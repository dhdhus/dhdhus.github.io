在本机跑 ComfyUI + Anima：一个 2B 动漫模型的完整落地记录

2026-11-10

这台机器上跑生成式模型有一段时间了，主力一直是 ComfyUI 便携版配 Anima。这套组合有意思的地方在于它不是 SD/SDXL 那条线上的东西——底模是 Cosmos 系的 DiT，文本编码器干脆换成了 Qwen3，整个工作流的接线方式、提示词写法、参数直觉都得重新校准一遍。

这篇把从装到跑、从单张到批量流水线的过程完整记一遍，参数都是本机实测的值，不是抄的推荐区间。

一、ComfyUI 装在哪，怎么起

便携版解压在 E:\AI\COMFYUI\ComfyUI_windows_portable\，实际干活的目录是：

版本 0.39.0。启动就是双击上级目录的 run_nvidia_gpu.bat，它自带一份嵌入式 Python，不需要系统里装 CUDA 环境。起来之后 Web 界面在 http://127.0.0.1:8188，同时这个端口本身就是完整的 HTTP API——后面批量出图全靠它。

出图默认落在 output\<filename_prefix 前缀>\ 下面，前缀在 SaveImage 节点里填，所以可以按项目分子目录，不会和别的批次混在一起。

便携版有个细节：models\diffusion_models 和老版本叫的 models\unet 其实是同一个位置，ComfyUI 两个名字都认。放哪边都行，但别两边都放一份，白占硬盘。

二、Anima 是什么

Anima 是 CircleStone Labs 和 Comfy Org 合作的东西，几个关键事实直接决定后面怎么用：

项目 内容
架构 2B DiT（Diffusion Transformer），不是 SDXL 血统
底模 NVIDIA Cosmos-Predict2-2B-Text2Image
文本编码器 Qwen3-0.6B
VAE Qwen-Image VAE
主模型体积 约 4.18 GB（safetensors）
显存 不量化约 7 GB 可跑
训练数据 数百万动漫插画 + 约 80 万非动漫艺术作品，无合成数据
动漫数据截止 2025-09
许可 模型权重非商用；生成图可商用

版本线有好几条：

  • Base v1.0：基座
  • Aesthetic v1.0 / v1.0b / v1.1：调过美学的版本，本机用的是 v1.1
  • Turbo v1.0 / v1.1：少步数版本
  • preview1–3：早期预览

这几个版本共用同一套 CLIP 和 VAE。也就是说换主模型的时候，另外两个文件不用动——但如果哪天换了编码器或 VAE，三件套必须一起换，混搭出来的图是糊的、颜色也是错的。这三个文件是一次训练里配套产出的，没有独立替换的余地。

三、三件套怎么挂

工作流开头三个 Loader 节点，对应三个文件：

节点 文件 放在 关键设置
UNETLoader anima-aesthetic-v1.1.safetensors models\diffusion_models\ weight_dtype 用 default
CLIPLoader qwen_3_06b_base.safetensors models\text_encoders\ type 选 stable_diffusion
VAELoader qwen_image_vae.safetensors models\vae\ 无

CLIPLoader 那个 type 是第一个坑。下拉框里没有 “qwen” 这个选项，第一次挂的时候很容易以为要选 qwen_image 之类。实际上选 stable_diffusion 就对了——它只是告诉 ComfyUI 按通用文本编码器的方式去加载这个权重，Qwen3 本身的结构是能识别的。选错的话要么直接报错，要么加载成功但输出一堆噪声。

五、参数

本机固定的这一组：

参数 值 说明
分辨率 1024×1344 竖构图，接近 3:4
batch_size 2 一次两张，便于对比 seed
steps 32 官方区间 30–50
cfg 4.5 官方区间 4–5
sampler er_sde 中性平涂，默认选择
scheduler simple 够用
denoise 1.0 文生图必须 1.0

几个值得说的地方：

CFG 只有 4.5。 从 SDXL 迁过来的人第一反应会觉得太低——SDXL 常规是 7。但 Anima 的文本编码器是 Qwen3-0.6B，语义理解强度比 CLIP-L 高一个量级，不需要靠高 CFG 硬拉提示词权重。CFG 往上推到 6 以上，画面会开始过饱和、边缘发硬，典型的”用力过猛”。

分辨率上限 1536。 官方给的区间是 512²–1536²。超过 1536 之后不是崩，而是开始出现重复构图——同一张图里出现两个一样的局部，或者脸部结构塌陷。竖图 1024×1344 是这套模型比较舒服的一个点。

batch_size 用 2 而不是 1。 不是为了省时间，是为了对比：同一组提示词、同一轮里出两张不同 seed 的图，哪张好一眼就能看出来。批量跑的时候这个习惯很有用。

六、采样器和调度器怎么选

ComfyUI 里能选的采样器一大堆，针对 Anima 实际有意义的就四个：

  • er_sde：中性平涂，线条干净、颜色不飘，是默认值，也是绝大多数情况下的正确选择
  • euler_ancestral：线条更柔，画面更”呼吸”，适合要氛围感的场景
  • dpmpp_2m_sde_gpu：最”有想法”的一个，构图和光影经常给你惊喜，但也经常跑偏——适合探索，不适合定稿
  • euler：最稳的一个，配 Turbo / Aesthetic 版本时用

有个容易踩的坑：ComfyUI 里没有 euler_a。网上很多 SD 的教程写 euler_a，在这里找不到，对应的是 euler_ancestral，全名。直接照抄会得到”节点参数不合法”的报错。

调度器这边 simple 就够，追求绘画质感可以上 beta57——但它来自 RES4LYF 节点包，得先装那个自定义节点，不是内置的。

七、提示词怎么写

Anima 的提示词结构和 SD 系有一定差别，尤其是权重和流派标签的处理。

顺序大致是：

标签格式：

  • 统一小写
  • 空格代替下划线（long hair 而不是 long_hair）
  • 唯一保留双下划线命名的是 score_* 系列
  • 画师必须带 @ 前缀，写成 @artist_name

Aesthetic 版不要用 score_*。 正向反向都别写。这版模型已经把质量分内化了，再塞 score_9, score_8_up 之类的标签反而会干扰。这是 Base 版和 Aesthetic 版在提示词上最大的区别。

权重要比 SDXL 给得更大。 SDXL 里 (chibi:1.2) 已经很重了，这里得 (chibi:2) 才有同样的效果。原因是 DiT 的注意力分布和 UNet 不一样，弱权重基本被忽略。这是实际调参时最需要重新建立直觉的一点。

标签和自然语言可以混写。 Qwen3 编码器的理解力是这套模型最大的亮点——你可以直接写英文句子描述场景，不用非得翻译成 booru 标签。纯自然语言的话至少写两句，一句话信息量太少反而会让模型自由发挥。

八、把单张变成批量流水线

ComfyUI 的 Web 界面适合调参，不适合量产。真正跑起来是靠 API + 一个 Node 脚本。

5 个够用的端点

方法 路径 用途
GET /system_stats 探活，看服务在不在
POST /prompt 提交任务，body 里放 prompt（整张节点图）+ client_id
GET /history/{prompt_id} 查结果，从 outputs[].images 取文件名
GET /queue 看 queue_running / queue_pending
POST /interrupt 中断当前正在跑的那张

POST /prompt 提交的就是上面那段 JSON——同一份工作流，脚本里当字符串模板用，每次替换 seed 和提示词就行。返回一个 prompt_id，之后拿它去 /history 轮询。

循环逻辑

脚本（generate_roccia_cg.cjs）干的事其实很朴素：

  1. 启动时解析桌面的 markdown 提示词包，全部读进内存
  2. 逐条 POST /prompt，每 5 秒轮询一次 /history/{id}
  3. 出图后往 roccia_cg.log 追加一行记录
  4. 一轮跑完换一批随机 seed，从头再来，无限循环
  5. /system_stats 探不通就每 30 秒重试，不崩

第 1 步和第 4 步之间有个隐性的约束：提示词只在启动时解析一次。改了 markdown 文件不重启进程，新词不会生效——脚本还按内存里那份旧的跑，日志看起来一切正常，图就是不对。这个坑我踩过一次，排查了半天才发现是缓存。

两个运维细节

别多开。 这种”无限循环”的脚本很容易在自己没注意的时候跑了两份，两边的任务同时往队列里塞，出一堆重复图。跑之前先 tasklist 看一眼。

/interrupt 只中断当前那张，不清队列。 想整体停下来，中断之后还得把队列里排着的任务清掉，否则它会接着跑下一张。

九、调参经验

跑了几十批之后攒下来的一些结论，都是”改了之后肉眼可见”的那种：

人物占画面比例靠取景标签控制。 cowboy shot（七分身）、upper body（半身）、close-up（特写）加权重就能拉。这是比调分辨率有效得多的手段。

背景喧宾夺主的时候，是给背景降权而不是删标签。 把 (detailed background:0.7) 加上，场景标签从 4 条压到 2 条，光照标签从 4 条减到 2–3 条，人物立刻就”凸”出来了。直接删掉场景标签会让背景变成一片死白，更难看。

单人要写死。 (solo:1.9) 加上加权负向（extra person / background person / distant figure / silhouette）才能压住背景里冒出来的人影。只写 solo 不加重，权重基本被稀释掉了。

光影是叠出来的。 想要那种丁达尔光柱的效果，单写一个 god rays 没用，得一整套：

机位别全用一种。 from below:1.2、from above:1.2 配 fisheye:1.08、perspective distortion:1.05 能让一批图看起来不像复制粘贴。但这类特殊机位控制在全部提示词的 20% 以内——超过这个比例，整批图会显得很”浮”，反而没有稳定的基准视角。

同名标签会去重，权重会丢。 提示词里同一个标签出现两次，保留的是第一次的那个，后面的权重直接作废。所以调权重的时候改第一个出现的位置。

十、踩坑清单

一次记清楚，省得下次再查：

  1. CLIPLoader 的 type 选 stable_diffusion，别找 qwen 选项
  2. 没有 euler_a，是 euler_ancestral
  3. Aesthetic 版别写 score_*，正负向都别写
  4. 权重要给大，SDXL 的 1.2 在这里等于没写
  5. 改提示词必须重启脚本，它是启动时一次性解析的
  6. 别多开循环进程，会重复提交任务
  7. /interrupt 不清队列，停完记得清
  8. 分辨率别超 1536，会出现重复构图
  9. CFG 别超 6，过饱和、边缘发硬
  10. 三件套必须配套，换一个就得换全套

这套东西跑顺之后，出一批图基本是”写 md → 起脚本 → 去看日志”三步，不需要盯着界面。ComfyUI 的 API 设计得比想象中干净，/prompt 吃 JSON、/history 吐文件名，中间没有多余的状态——比起很多生成式框架的 SDK，反而更适合直接拿 HTTP 拼流水线。
