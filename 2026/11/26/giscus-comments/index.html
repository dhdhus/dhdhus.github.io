给静态博客装个评论区

2026-11-26

上一篇说静态站的天花板是”没地方存数据”，评论区就是最典型的例子。但真做起来发现，评论区根本不需要我自己存数据 —— 把别人的服务嵌进来就行。

选 giscus 的原因

GitHub Pages 只吐静态文件，所以动态部分必须外包。可选的路子有几条：

  • Waline / Twikoo：要自己起一个 Node 服务，Vercel 免费额度够用，但多一层依赖
  • Cloudflare Worker + D1：灵活，但要迁 DNS
  • giscus：把 GitHub Discussions 当数据库，评论就是仓库里的讨论帖

第三条最省事。零服务器、零数据库、零费用，数据还在自己仓库里，哪天不用了把 Discussions 关掉就行。唯一的门槛是评论者得有 GitHub 账号 —— 对技术博客来说不算门槛。

三步配置

全程在网页上点，不用改代码：

  1. 仓库 Settings → General → Features → 勾上 Discussions
  2. 到 https://github.com/apps/giscus 安装，只授权这一个仓库
  3. 打开 https://giscus.app/zh-CN ，填仓库名，页面会给出 repo-id 和 category-id

那个 150px 的空白

配好之后打开文章页，评论区一片白。查了才发现：

但 client.js、default.css、/zh-CN/widget 全是 200，网络面板里一点红都没有。

做了个对照实验才找到原因。把完全相同的 12 个 data-* 属性做成静态页 public/_gtest.html，放在站点根目录 —— iframe 正常渲染成 372px。同一份 HTML 挪到 public/2026/11/24/static-limits/_t.html，也就是深两层的路径 —— 永远 150px、永远透明。

差别只有路径深度。这不是 category_id 的问题，不是跨域，也不是暗色主题。

真凶是 giscus 自带的 data-loading="lazy"。它内部用 IntersectionObserver 判断”有没有滚到评论区”，然后才 postMessage 告诉父页面还原高度。可它观察的目标在跨进程 iframe 里，加上我这套布局的滚动容器，那个”进入视口”的信号压根没触发过。轮询时序是这样的：

改法：自己控制挂载时机

把 lazy 去掉，改成我自己盯着容器。mount() 里注入 script 时一律 eager：

rootMargin: '600px 0px' 的意思是提前 600px 就开始加载，读者滚到底的时候评论一般已经渲染好了。那个 8 秒兜底是防”用户从锚点直接跳进来、IntersectionObserver 没触发”这种情况。

结果

现在每篇文章底部都有一个评论框。不用登录也能看，想说话就得用 GitHub 账号登一次。

回头想想，最开始那个”加后端”的念头 —— 数据库、鉴权、接口、防刷 —— 在评论区这个需求上一条都不需要。静态站缺的是”存东西的地方”，而 GitHub Discussions 恰好就是免费的存东西的地方。真正的成本不是服务器，是接受”这块 UI 不归我管”。

不过这只是把别人的服务嵌进来。下一篇想说的话题是：如果要做阅读量、点赞这种自己定义的数据，就没这么便宜了。
